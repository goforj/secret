# v0.1.0 release notes (draft)

Publish these notes only after all seven module tags resolve and pass the public-consumer verifier. The repository is currently a release candidate, not a published version.

Read, replace, and delete secrets through a small Go API. Bind application names once and choose AWS Secrets Manager, Google Secret Manager, Azure Key Vault, Vault KV v2, or authenticated encrypted local files.

- Local files use AES-256-GCM with caller-managed keys. Reads accept previous keys, writes use the current key, and explicit rotation migrates existing files.
- Narrow Reader, Writer, and Deleter interfaces keep provider details in construction. Errors support classification without retaining provider responses or secret values.
- File confinement, exact values, cancellation, concurrent mutations, persistent-key recovery, and process crash/restart behavior have regression coverage.

After publication, install only the modules your application needs:

```sh
go get github.com/goforj/secret@v0.1.0
go get github.com/goforj/secret/secrettest@v0.1.0
go get github.com/goforj/secret/driver/filesecret@v0.1.0
go get github.com/goforj/secret/driver/awssecret@v0.1.0
go get github.com/goforj/secret/driver/azuresecret@v0.1.0
go get github.com/goforj/secret/driver/gcpsecret@v0.1.0
go get github.com/goforj/secret/driver/vaultsecret@v0.1.0
```

The core, test support, and AWS driver require Go 1.24.4. File support requires Go 1.25.12+, Go 1.26.5+, or stable Go 1.27+. The remaining SDK drivers require Go 1.26. These optional requirements do not raise the core minimum.

This is the initial release, with no earlier public version to upgrade. Existing plaintext mounts remain an explicit read-only API; encrypted storage never silently migrates them. Keys must be retained separately, and rotation is not a transaction across files. Cloud integration coverage uses pinned emulators and a real Vault server; dedicated hosted AWS, Azure, and Google accounts remain unverified.

See [provider contracts](../drivers.md), the [release review](../review.md), and [publication verification](../development.md#module-publication) for operational limits and detailed evidence.
